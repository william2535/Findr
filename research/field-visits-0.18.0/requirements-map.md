## Catalogue scope

The supplied route catalogue is P01–P09 (shared power/cabling), F01–F15 (fire), A01–A10 (access), C01–C12 (CCTV) and I01–I12 (intruder): **58 routes**. T0 observation and T1 bounded inference are the shipped generic scope. T2 action/range candidates remain draft. T3 specialist/design work records evidence and owner/referral requirements rather than generating an operational procedure.

The original warden-call guides are existing functionality outside the four-discipline research pack. They must remain accessible; this change must not imply that a newly authored warden-specific route catalogue exists.

## Acceptance evidence to record at integration

The supplied T01–T36 fixtures are behaviour requirements, including assertions about suggestions that must be suppressed. Unit coverage should test event identity/migration, exact raw results, gate precedence, comparable states, blocked/unknown progression, profile conflicts, impairments, redacted exports and source revision snapshots. Browser coverage should exercise start → question → quick test → manual/hint return → handover/export → offline reopening at portrait width. Keyboard-safe controls need a browser viewport check and are not a claim of physical iPhone certification.

Do not replace missing model review with successful software tests. Likewise, do not describe a build as a website deployment or updated signed APK. The release owner records the final test counts, checked browser flows, committed source, deployed version and any remaining draft scope.
